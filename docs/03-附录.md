# 附录 — 通用约定 · 错误码 · 枚举

本文为公共参考，所有接口文档均以此为准则。

---

## 1. 两类接口风格

### 1.1 下游接口（`/v1`，OpenAI 兼容）

- 认证：`Authorization: Bearer <网关Key>`。
- 成功/失败响应体、错误码均为 OpenAI 风格（见 [chat-completions.md](01-下游接口/chat-completions.md#4-错误下游)）。
- 失败 HTTP 状态码区分语义（400/401/403/404/429/5xx）。
- 费用字段**不对外暴露**。

### 1.2 管理端接口（`/admin`，业务码风格）

- 认证：无（内网部署）。内容协商：`Content-Type: application/json`。
- HTTP 状态恒为 `200`，业务结果由 `code` 表达：

```
// 成功
{ "code": 0, "message": "ok", "data": { ... } }

// 失败
{ "code": 10100, "message": "用户不存在", "data": null }
```

| 字段 | 说明 |
| --- | --- |
| `code` | 0 = 成功；非 0 = 业务错误（见 §3） |
| `message` | 人类可读信息 |
| `data` | 成功时业务数据；失败为 `null` |

- 分页请求：`page`（默认 1）、`page_size`（默认 20，最大 100）。分页响应 data：

```json
{ "list": ["..."], "total": 123, "page": 1, "page_size": 20 }
```

## 2. 数据类型与格式约定

| 类型 | 约定 |
| --- | --- |
| 金额 / 单价（`DECIMAL`） | **字符串**传输（如 `"6.21000000"`），接收端同样接受字符串。明细单位见各文档：余额与流水最多 6 位小数，单价最多 8 位小数，`total_cost` 8 位小数 |
| 时间戳 | RFC3339（如 `2026-09-08T05:00:01Z` 或 `2026-09-08T13:00:01+08:00`） |
| 日期（日统计） | `YYYY-MM-DD`；自然日按 `timezone` 切分（默认 UTC） |
| 计数 / token / 次数 | 整数（JSON number） |
| ID | 整数 |
| JSONB 扩展字段 | 对象，随上下文自由扩展 |

### 通用响应头

| Header | 位置 | 说明 |
| --- | --- | --- |
| `X-Request-Id` | 下游响应 | 网关请求 ID，等于 `usage_logs.request_id`，对账凭据 |
| `Retry-After` | 下游 429 响应 | 建议重试秒数 |
| `X-Request-Id` | 管理端响应 | 网关请求 ID（便于服务端日志关联） |

## 3. 管理端业务错误码

### 3.1 通用

| code | 含义 |
| --- | --- |
| `0` | 成功 |
| `10000` | 参数缺失或格式非法（具体字段见 message） |
| `10001` | JSON 解析失败 |
| `10002` | 资源不存在（泛化，优先使用各模块细化码） |
| `10003` | 重复创建（唯一键冲突） |
| `10004` | 操作不被当前状态允许 |
| `10005` | 内部错误（服务器异常） |
| `10006` | 请求体过大 |

### 3.2 模块错误码

| code | 含义 | 归属 |
| --- | --- | --- |
| `10100` | 用户不存在 | users-keys |
| `10101` | 用户状态不允许该操作 | users-keys |
| `10102` | 充值金额必须 > 0 | users-keys |
| `10200` | 网关 Key 不存在 | users-keys |
| `10201` | key_name 已存在 | users-keys |
| `10202` | prefix 非法 | users-keys |
| `10203` | 用户停用，禁止创建/启用 Key | users-keys |
| `20000` | 渠道不存在 | channels |
| `20001` | 渠道已停用，无法操作 | channels |
| `20002` | 渠道下已存在该 model_name | channels |
| `20003` | 模型映射不存在 | channels |
| `20004` | 渠道必填字段为空 | channels |
| `20005` | 渠道仍被引用，需先停用 | channels |
| `30000` | 定价记录不存在 | pricing |
| `30001` | 价格不合法（负数/位数超限） | pricing |
| `30002` | 定价对应模型映射不存在 | pricing |
| `30003` | currency 不支持 | pricing |
| `40000` | 限流规则不存在 | rate-limits |
| `40001` | target_type/metric 非法 | rate-limits |
| `40002` | limit_value/window_seconds 非法 | rate-limits |
| `40003` | queue 模式缺超时配置 | rate-limits |
| `50000` | 日志不存在 | stats-billing |
| `50001` | 时间范围非法 | stats-billing |
| `50002` | 日期格式非法 | stats-billing |

## 4. 枚举字典

### 4.1 users

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `user_group` | `default` / `vip` / `enterprise` | 路由与限流分组 |
| `status` | `active` / `suspended` / `deleted` | suspended 拒绝调用可恢复；deleted 逻辑删除 |

### 4.2 client_api_keys

| 字段 | 取值/说明 |
| --- | --- |
| `permissions.models` | 对外模型名数组；`["*"]` 全部 |
| `rate_limit_overrides` | 覆盖字段：`rpm/tpm/rpd/tpd/concurrency` |
| `expires_at` | null = 永不过期 |
| `is_active` | bool |

### 4.3 channels / channel_models

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `channels.status` | `1` 启用 / `0` 停用 | |
| `channels.weight` | int | 负载权重，默认 100 |
| `channels.priority` | int | 越大越优先，默认 0 |
| `channels.auth_type` | `bearer` | 预留扩展 |
| `channel_models.enabled` | bool | false 则不参与路由 |

### 4.4 rate_limit_rules

| 字段 | 取值 |
| --- | --- |
| `target_type` | `global` / `user` / `api_key` / `model` / `channel` |
| `metric` | `rpm`（次/分） / `tpm`（token/分） / `rpd`（次/日） / `tpd`（token/日） / `concurrency`（并发） |
| `action` | `reject` / `queue` |

### 4.5 资金流水 `tx_type`（balance_transactions）

| 取值 | 金额方向 | 语义 |
| --- | --- | --- |
| `recharge` | + | 充值入账 |
| `freeze` | − | 请求预冻结（available→frozen） |
| `consume` | − | 实际消费（从冻结中确认） |
| `unfreeze` | + | 释放冻结（多退） |
| `refund` | + | 人工/异常退款 |

### 4.6 usage_logs

| 字段 | 取值/说明 |
| --- | --- |
| `status` | `success` / `error`；`error_code` 记录失败原因 |
| `error_code` | 参考下游错误码 `code`（如下游看到 `502 upstream_error`，此处 `error_code=upstream_error`） |
| `model` | 对外模型名；`upstream_model` 上游真实模型名 |
| `ttft_ms` | 流式首 token 时间；非流式可为 null |

### 4.7 下游错误码 `code`（OpenAI error 对象）

| code | HTTP | 场景 |
| --- | --- | --- |
| `invalid_request_error` | 400 | 请求体非法 |
| `invalid_api_key` | 401 | Key 无效/不存在 |
| `key_expired` | 401 | Key 过期 |
| `key_disabled` | 401 | Key 停用 |
| `account_suspended` | 403 | 用户停用 |
| `model_not_allowed` | 403 | 超出 Key 模型白名单 |
| `model_not_found` | 404 | 网关无该模型可用渠道 |
| `rate_limit_exceeded` | 429 | 限速/限额命中 |
| `insufficient_quota` | 429 | 余额不足（预冻结失败） |
| `engine_overloaded` | 429 | 排队超时 |
| `internal_error` | 500 | 网关内部 |
| `upstream_error` | 502 | 无健康上游可路由 |
| `upstream_timeout` | 504 | 上游转发超时 |

## 5. 其它通用说明

- **时间范围上限**：单次统计查询跨度默认不超过 31 天（`50001`）。
- **幂等**：充值建议携带 `related_order_id`（网关侧去重）；创建类接口可携带可选 `X-Idempotency-Key`。
- **兼容性**：下游接口尽力保持 OpenAI 兼容；未知字段透传；不返回网关内部信息（渠道名、上游模型、费用）。
- 文档中"上游渠道自身的业务错误透传"适用于上游返回 4xx 且未触发熔断的场景。
