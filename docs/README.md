# MyApi — LLM API 网关接口文档

MyApi 是一个面向 LLM 的 **API 网关 / 统一接入层**。它向下游业务方提供 **OpenAI 兼容协议** 的统一入口，同时隐藏上游多个 LLM 渠道（OpenAI、Anthropic、各类中转等）的差异与密钥；负责对下游做鉴权、限速、限额与计费，对上游做模型路由、负载均衡、熔断与健康切换。

> 本文档仅描述接口契约（请求 / 响应 / 语义），不含内部实现细节。
> 数据库结构参见仓库根目录 `数据库表设计.txt`。

## 1. 网关位置

```
                         ┌──────────────────────────────────────────────┐
                         │                    MyApi                     │
                         │                                              │
  下游业务方              │   ┌──────────┐    ┌───────────────────────┐  │
┌─────────────┐  OpenAI  │   │  API 层   │──▶│  鉴权 · 限速 · 限额    │ │
│  App / SDK  │─  协议───▶│   │(chat/comp)│   │ (网关Key → 用户/配额) │  │
└─────────────┘  1个Key   │   └──────────┘    └──────────┬────────────┘  │
                          │                             │                │
                          │                     ┌───────▼───────────────┐│
                          │                     │   模型路由 · 负载均衡   ││
                          │                     │   熔断 · 健康检查      ││
                          │                     └───────┬───────────────┘│
                          │                             │                │
                          │              ┌──────────────┼──────────────┐ │
                          │              ▼              ▼              ▼ │
                          │       ┌──────────┐   ┌──────────┐   ┌──────────┐
                          │       │ 上游渠道A │   │ 上游渠道B │   │ 上游渠道C│  (可动态增删)
                          │       └──────────┘   └──────────┘   └──────────┘
                          │   (用量统计 · 费用计量 · 余额结算 贯穿全链路)  │ 
                          └─────────────────────────────────────────────┘
```

核心原则：

- **下游只见一个网关 Key**，Key 对应到某个"用户"（下游租户 / 调用方）。
- 网关 Key 指向用户，用户余额为该 Key 背后的计费主体。
- 同一个对外模型名（如 `gpt-4`）可映射到多个上游渠道，由网关做负载均衡与故障切换。
- 费用以「渠道 × 模型」的单价快照为准，每次调用实时结算。

## 3. 两套接口风格

| 维度 | 下游接口（/v1） | 管理端接口（/admin） |
| --- | --- | --- |
| 面向对象 | 外部业务方 / SDK | 平台运营方（内网） |
| 认证 | `Authorization: Bearer sk-...`（网关 Key） | 不设认证（依赖内网 / 网关自身访问控制） |
| 协议 | OpenAI Chat Completions（含 SSE） | 自定义 JSON-RPC 风格 REST |
| 成功响应 | OpenAI 原样结构 | `{"code":0,"message":"ok","data":...}` |
| 错误响应 | OpenAI 兼容：`{"error":{"message","type","param","code"}}` | `{"code":非0,"message":...,"data":null}` |
| 金额字段 | 不出现（费用仅服务端记账） | 以字符串表示，避免浮点精度丢失 |

> 详情见 [03-附录.md](03-附录.md)。

## 4. 关键概念

| 概念 | 说明 |
| --- | --- |
| 用户 (user) | 下游计费主体 / 租户，拥有余额与多个网关 Key |
| 网关 Key (client_api_key) | 下游调用凭证，归属某个用户；可限定模型白名单、单 Key 限速 |
| 渠道 (channel) | 一个上游 LLM 服务（如某 OpenAI 中转），含独立 base_url 与密钥 |
| 渠道模型 (channel_model) | 渠道对某"对外模型名"的实际上游模型名映射 |
| 对外模型名 | 下游在请求体中填写的 `model`，网关据此路由 |
| 单价 (model_pricing) | 渠道×模型 的输入/输出/cached 单价（美元 / 1M tokens） |
| 限流规则 (rate_limit_rules) | 按 global/user/key/model/channel 维度的 rpm/tpm/rpd/tpd/并发 规则 |
| 结算 | 每请求「预冻结估算费用 → 结束后按实际 usage 多退少补」 |

调用链：`网关Key → 用户`（鉴权、余额校验、用户级限流）→ `model → channel_model[]`（路由、负载均衡、熔断）→ 上游返回 → `结算 + usage_logs + 日汇总`。

## 5. 一个请求的完整生命周期（概要）

1. 下游携带 `Authorization: Bearer sk-xxx` 调用 `POST /v1/chat/completions`。
2. 网关解析 Key → 校验有效性 / 过期 / 权限 / 用户状态。
3. 用户级限速与限额检查（Redis），命中的 Key 级限速覆盖同时生效。
4. 估算本请求费用 → 从可用余额 **预冻结**（余额不足则 429 拒绝）。
5. 模型路由：按 `model` 匹配可用且健康的渠道模型，按权重/优先级负载均衡选择一个渠道。
6. 网关替换上游密钥与真实模型名，转发请求（流式则 SSE 逐段透传）。
7. 上游返回后按 usage 结算：记 `usage_logs`、更新 `user_daily_stats`、写 `balance_transactions`（consume/unfreeze），日终/按需供报表查询。

## 6. Base URL 约定

- 下游：`https://<gateway-host>/v1`（OpenAI SDK 只需把 `base_url` 指向此处）
- 管理端：`http://<gateway-host>:<admin-port>/admin` 或经网关内网路由
